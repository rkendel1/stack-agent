AppPort event observation (TypeScript, pnpm, vitest). Make event delivery honour the specification's authorization rules for subscriptions on every transport.
Problem: an application can declare events that require a permission to observe (e.g. documents.changed requires documents.read). A client lacking that permission, or with no session, is correctly refused when it subscribes to that event by name. Operators report such clients can still receive those protected events through other ways of subscribing that the specification also allows, both over a server connection and over the HTTP event stream (GET /appport/events). Clients that hold the permission must keep receiving their events.
Requirements: read the spec rules for subscriptions and delivery (spec/) and the server implementation first. Reproduce the leak against the starting commit with a test that fails there. Fix it in the responsible layer using AppPort's existing permission model, wildcard permissions included; no parallel authorization mechanism. Keep named-subscription behaviour (same refusals, error codes, deliveries). Cover a server connection and the HTTP SSE endpoint in regression tests. No wire-protocol, envelope or public API changes; no unrelated redesign; do not weaken or remove tests.
Acceptance: a session never receives an event it may not observe, however it subscribed; public events still reach every subscriber, anonymous included; permitted sessions (directly or via wildcard permission) still receive matching events; existing suite passes (pnpm test); new tests fail without the fix. Do not commit or push. Report the reproduction and its output, root cause, changed files, tests and results, and limitations.
