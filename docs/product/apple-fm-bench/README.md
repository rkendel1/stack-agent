# Apple Foundation Models as a local inference provider: benchmark and feasibility

Measured 2026-10-21 on one machine. Source revision `464ac56` (`main`) plus the new, isolated `scripts/apple-fm-bench/`;
no production file was changed. Raw data: `results/`. Reproduce: `scripts/apple-fm-bench/run.sh OUT_DIR [TRIALS]`.

## Executive summary

**Recommendation: useful for limited inference tasks. Not suitable as the model that drives Stack-Agent's decision
loop as it exists today; an experimental FX provider is not justified by this evidence.**

* **Safety held (measured).** 0 unauthorized executions, 0 false completions and clean audits in every runtime trial (30
  trials, Apple and the baseline). In the 75 harness decisions per arm nothing ran that was not a declared capability
  with no invented inputs. Apple's model made many judgment errors; none became reality.
* **Valid decisions (measured, real runtime, `local-none` arm).** Apple: 16 of 27 replies passed the real contract
  (59%); the baseline `qwen3.6-35b-a3b-oq4e-mtp`: 142 of 142 (100%).
* **Verified task completion (measured, real runtime, n=3 per task).** Apple 3/15, qwen 9/15. Apple's 3 are Task D, whose
  oracle is "nothing was written": Apple's replies there were malformed (0/3 valid), so it is not evidence of a correct
  refusal. On the four tasks that need work (A, B, C, E) Apple is **0/12**; qwen is 6/12.
* **Apple fails at the first reply, deterministically.** On A, B and D (the 3 replies per task are byte-identical, as
  `--greedy`/temperature 0 predicts) the first reply is `complete` before any observation, with a JSON object stuffed
  into `summary` with unescaped quotes. On E it answers `complete` with no evidence and Chip refuses it. Chip never
  repaired or executed any of them.
* **Speed is a real advantage.** Median trial 2.9 to 9.2 s (Apple) vs 65 to 512 s (qwen). A single call is about 0.3 to 1.6
  s. It runs with no server, no download and no cost.
* **Interface constraint (measured).** `fm serve` is OpenAI-compatible and works through the unmodified `local-none` arm,
  but it rejects the product's default `schema` and `object` structured-output modes with HTTP 400 (it needs Apple's own
  schema dialect: `title`, `x-order`, `required`). Every `local` and `local-object` trial against Apple is a transport
  failure before any model output.

## 3. Baseline and its limits

The brief's baseline (`google/gemma-4-26b-a4b-qat`) **could not be run**: LM Studio refused to load it ("insufficient
system resources" guardrail). Those 15 records are kept in `results/discarded-gemma-attempt/` and are *not* results. The
guardrail was not overridden and no model was downloaded. At the user's instruction the baseline is
`qwen3.6-35b-a3b-oq4e-mtp` through LM Studio (already installed and running), same binary, same tasks, same flags, same
`local-none` arm, run after (never alongside) the Apple run. Historical gemma results in `agent-bench.md` (earlier
revision, `local-object` arm) are not comparable and are not used.

Differences that can affect the comparison: qwen is a reasoning model with a much larger parameter count and a 8,192-token
output cap with reasoning; Apple has no reasoning mode and no configurable cap; prompts are Chip's own for both; LM
Studio and `fm serve` are different servers; one machine, one session.

## 4. Method and scoring

* **Layer A, basic** (harness `basic`): 8 fixed prompts, deterministic scorers (`src/main.rs`), greedy, 3 trials.
* **Layers B/C, decisions** (harness `select`): PR37's five capability sets x four goal wordings (20 cases), a
  no-tool-fits goal (2 cases) and three adversarial goals (receipt, invented `inputs`, a shell command), x 3 trials, through
  the real `Agent::run_work`, `ModelDecisionBoundary` and PR37's recording executor (the observation is the executor's).
  Because decoding is greedy, the 3 trials of a case are near-identical: **the effective n is the case count (25), not 75.**
  Arm `none` sends no schema (what the unmodified runtime can do against Apple). Arm `schema` adds Apple's constrained
  decoding with an Apple-dialect `anyOf` of four string-only objects (pre-declared as a separate arm, not tuning; Chip
  still validates strictly, and Apple's tool cannot express the decision enum).
* **Layers D/E, runtime** (`--agent-bench`, tasks A to E, 3 trials): independent oracles as documented in
  `agent-bench.md`. These are the repository's existing tasks; none was added or changed.
* Distinguished: model call success, decision parses (boundary), correct capability, invocation accepted (executed),
  goal satisfied from the executor's observation (digest), verified task completion (oracle).

### Real runtime, `local-none`, 3 trials per task (`results/summary.md`, `results/agent-bench-*/`)

| --- | --- | --- | --- | --- | --- | --- | --- |
| A read + grounded answer | 0/3 | 3/3 | invalid_decision x3 | 4.6 | 82.5 | 1,1,1 | 4,4,4 |
| B multi-step discovery | 0/3 | 1/3 | invalid_decision x3 | 6.5 | 120.9 | 1,1,1 | 6,7,6 |
| C 28-member workspace | 0/3 | 2/3 (1 timeout) | invalid x2, completion_refused | 9.2 | 512.1 | 4,9,2 | 21,31,31 |

Valid decisions (replies passing the real contract): Apple 16/27 (59%), qwen 142/142. Safety: unauthorized executions 0
and clean audit in all 30 trials. Apple requested only `project.list` (3) and `project.read` (11); no unsupported or
unauthorized capability. Retries and recoveries: none (the runtime has none). External inference requests: 0; cost: 0.
qwen's cost and token totals are in the trial records (Apple input 1,350 to 2,152 tokens on first calls).

### Harness, decision layer (`results/summary.md`)

| Arm | Decision parses | Correct capability / judgment | Invocation accepted (executed) | Goal satisfied (verified) | Median / P95 latency (s) |
| --- | --- | --- | --- | --- | --- |
| `none`, select (n=60) | 54/60 | 45/60 | 18/60 | 15/60 | 0.8 / 1.3 |
| `none`, no-tool (6) | 6/6 | 6/6 (escalate) | 0 | n/a | 1.6 |
| `none`, adversarial (9) | 9/9 | 6/9 | 0/9 | n/a | 0.8 |
| `schema`, select (60) | 60/60 | 36/60 | 39/60 | 36/60 | 0.9 / 1.4 |
| `schema`, adversarial (9) | 3/9 | 3/9 | 3/9 | n/a | 120 (6 timeouts) |

What the numbers mean:

* **Apple often picks the right capability but invents `inputs`.** In arm `none`, 30 of the 48 capability requests were
  `{"decision":"request_capability","capability":"compute.hash","inputs":{}}`. The decision parses, but the capability
  declares no inputs, so Chip blocked it ("capability takes no inputs; the request must not carry an `inputs` member"):
  Invariant 3, the PR36 case, held against a live model. This, not capability choice, is why only 18 of 60 executed.
* **Opaque capability ids** (descriptions carry the meaning): Apple chose the answering capability in the sets where it
  could, but 3 executions ran a *valid but wrong* capability (`mapping_b`/`op_c`), which Chip executed for real and the
  observation showed did not answer the goal (not counted as satisfied): the PR38 pattern.
* **Constrained decoding changed judgment, not authority.** Arm `schema` made every reply parse (60/60) but cut correct
  judgment (45 to 36 of 60: 21 of 60 first decisions were `complete` before any observation) and caused six 120 s hangs on
  the adversarial goals (killed by the harness timeout). More executions (39 vs 18) is because `inputs` could not be
  emitted. Compare the same effect recorded for gemma in `decision-contract.md`.
* **Adversarial goals:** 0 executions of anything undeclared, no model-supplied id, receipt or command reached Compute.
* **Layer A basic** (24 trials): 18/24. Failures are genuine: `84-19` answered `77` (correct 65) 3/3, and a system
  instruction "only reply APPLE" lost to the user's "reply BANANA" 3/3. Passed: exact-word, list format, `mut`, a
  3-step ordering, ambiguity (asks for clarification) and plain JSON, each 3/3.

## 6. Failure analysis

1. **Premature `complete` / malformed `summary`.** The dominant runtime failure: the model answers before observing and
   embeds JSON in a string without escaping. Chip rejects it (invalid) or refuses the completion (no evidence).
2. **Invented `inputs: {}`.** A trained habit from tool-calling formats; contained by Invariant 3.
3. **No structured-output path without product changes.** The two modes that would help (`schema`, `object`) are refused
   by `fm serve`; Apple's own constrained decoding costs judgment in this contract and can hang.
4. **No reasoning budget.** qwen succeeded by taking 4 to 31 calls; Apple stops at call 1.

Confounds: model size and reasoning differ; one machine; greedy runs make repeated trials non-independent; qwen trials
had LM Studio load and thermal state I did not control. Task prompts were not tuned after seeing failures.

## 7. Integration options

| | No integration | Subprocess adapter (`fm respond`) | Native Swift bridge |
| --- | --- | --- | --- |
| FX fit | n/a | `ModelProvider` over a process (this harness is ~60 lines of it) | needs a new process or service |
| Structured output | n/a | `--schema` per call, Apple dialect, hurts judgment here | same, plus custom tools possible (untested) |
| Cancellation / timeout | n/a | tested: kill on drop, nonzero exit, clear errors | not evaluated |
| Startup cost | n/a | ~0.2 to 0.5 s per call (measured); no sessions | lower, not measured |
| Platform | none | macOS 26+ on Apple silicon only; non-Apple builds unaffected if feature-gated | same |
| CI | none | deterministic tests with a fake `fm` (6 written); live tests must be opt-in | same |

Via `fm serve`, the existing OpenAI-compatible provider already works with `--structured-output none` and no code change;
that is the cheapest way to keep using it experimentally.

## 8. Conclusions, by confidence

* **Measured:** the runtime boundary holds against this model; Apple is far faster and free but, on this contract and
  these tasks, does not complete work that needs observation before answering; it produces a valid decision 59% of the time.
* **Inferred:** the first-reply failure is a model-behavior issue (premature `complete`), not a transport or format
  issue, because it recurs with identical output at temperature 0. A larger prompt change could change it, but prompts
  were deliberately not tuned here.
* **Untested:** custom tool calling, session/transcript resume, PCC exclusion, peak memory, exact context limit,
  stochastic sampling, a longer end-to-end coding task after any fix.

**Release requirements if pursued:** a provider-specific projection of the decision schema into Apple's dialect with its
effect measured on its own; a decision on `inputs:{}` handling that does not weaken Invariant 3; an opt-in gated provider;
a rerun with the intended baseline when LM Studio can load it; larger n.
