## Summary

smolagents is a small (about 12.8k lines of Python), single-process ReAct loop with two action
formats: **structured tool calls** (`ToolCallingAgent`) and **Python code as the action**
(`CodeAgent`, run by an AST-walking interpreter or a remote sandbox). Its useful ideas are
compact: a typed step memory projected into chat messages, **errors fed back as observations**,
a terminal `final_answer` tool gated by caller-supplied **completion checks**, schema validation of
tool arguments, a text-JSON fallback for models without native tool calling, and JSON-schema
constrained output for the code agent on servers that support it. It has **no persistence,
resume, approval or idempotency** of any kind. When the step budget runs out, it asks the model
for an answer with no tools and returns that answer. Its code-as-action mode bypasses argument
schema validation and allows partial effects inside one action. Both behaviours conflict directly
with stack-agent's closed decision contract.

## Findings

### Loop (`MultiStepAgent`)

* `run()` sets the task, optionally resets memory, appends a `TaskStep`, then drives `_run_stream`. With `stream=True` it returns the generator itself ([agents.py:496](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L496)) `[source]`.
* The loop runs while there is no final answer and `step_number <= max_steps` (default 20). Each iteration may run a planning step, then one `ActionStep` via the subclass `_step_stream` `[source]` ([agents.py:540](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L540)).
* **Error policy.** `AgentGenerationError` (the model backend failed) is re-raised and ends the run ([agents.py:594](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L594)). Every other `AgentError` (parse error, tool-call error, tool execution error, failed final-answer check) is stored in `action_step.error`, and the loop continues, consuming a step ([agents.py:597](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L597)) `[source]`. The error text reaches the model as a tool-response message ending with *"Now let's retry: take care not to repeat previous errors! If you have retried several times, try a completely different approach."* ([memory.py:142](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/memory.py#L142)) `[source]` `[experiment]` (`logs/e1_cases.json`, `model_saw_after_each_call`).
* **Budget exhaustion fabricates an answer.** When `max_steps` is reached, `_handle_max_steps_reached` calls `provide_final_answer`, which makes one more model call with no tools ("Based on the above, please provide an answer…") and returns that text as the run's output ([agents.py:607](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L607), [agents.py:810](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L810)) `[source]`. In `tc_max_steps` no charge happened, yet `run()` returned "I think the account was charged 12.5." The failure is visible only as `RunResult.state == "max_steps_error"` with `return_full_result=True` ([agents.py:524](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L524)) `[experiment]`.
* **Planning.** With `planning_interval=k`, a `PlanningStep` runs at step 1 and every k steps. It uses its own prompts and stop sequence `<end_plan>`. Plan updates are built from `write_memory_to_messages(summary_mode=True)`, which drops the system prompt, previous plans and the model's raw outputs, keeping tool calls, observations and errors ([agents.py:551](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L551), [agents.py:684](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L684), [memory.py:174](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/memory.py#L174)) `[source]`.
* **Final answer.** `final_answer` is an ordinary tool, added by default ([agents.py:389](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L389)). In ToolCallingAgent, a `final_answer` sent together with other tool calls raises an error *after* the other calls have run in parallel ([agents.py:1342](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L1342)) `[source]` `[inferred]`: the effects happen, then the step is marked as an error.
* **`final_answer_checks`.** These are caller predicates `(answer, memory, agent) -> bool`, run before the answer is accepted. A failed check (an exception or `False`) becomes an `AgentError` observation, and the loop continues ([agents.py:590](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L590), [agents.py:613](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L613)) `[source]`. In `tc_final_answer_check` a premature answer was refused and the task then completed correctly: 4 model calls, 1 charge `[experiment]`. This is the same idea as stack-agent's "completion refused unless required observations exist", but expressed as user predicates over memory.

### ToolCallingAgent

* The model is called with `tools_to_call_from` and stop sequences `Observation:` / `Calling tools:` ([agents.py:1276](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L1276)). Base `Model._prepare_completion_kwargs` defaults to **`tool_choice="required"`** whenever tools are passed ([models.py:510](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/models.py#L510)) `[source]`. With an OpenAI-compatible server, the model must therefore emit a tool call every turn, and `final_answer` is one of the tools: in effect a closed action set enforced by the server `[inferred]`.
* **Models without native tool calling.** If the reply has no `tool_calls`, `Model.parse_tool_calls` extracts JSON from the text using the first `{` to the last `}` ([agents.py:1329](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L1329), [models.py:583](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/models.py#L583), [models.py:400](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/models.py#L400), [utils.py:166](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/utils.py#L166)) `[source]`. `tc_text_toolcall` verified with 3 model calls `[experiment]`. Parsing is lenient. It is not a repair: malformed JSON raises `AgentParsingError` with the decode position, which is fed back (`tc_bad_json`: 4 calls, verified) `[experiment]`.
* **Argument validation.** `validate_tool_arguments` checks unknown keys, JSON type and required keys against `Tool.inputs`, and coerces integer to number ([tools.py:1361](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/tools.py#L1361)). Failures raise `AgentToolCallError` *before* the tool runs ([agents.py:1476](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L1476)) `[source]`. Missing `amount` produced "Argument amount is required". A string `amount` produced "Argument amount has type 'string' but should be 'number'". Both recovered on the next model call with no extra effect `[experiment]`. The error message omits the `Call id`, because `memory_step.tool_calls` is assigned only after all calls finish ([agents.py:1436](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L1436)) `[source]` `[experiment]`.
* Multiple tool calls in one reply run **in parallel threads** (`ThreadPoolExecutor`) with no ordering or effect accounting ([agents.py:1426](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L1426)) `[source]`.
* **Implicit state substitution.** Any string argument that equals a key in `agent.state` is silently replaced by the state value ([agents.py:1444](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L1444)) `[source]`. This is a confused-deputy hazard for consequential tools `[inferred]`.
* A tool exception becomes `AgentToolExecutionError` with "Please try again or use another tool" ([agents.py:1486](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L1486)) `[source]`.

### CodeAgent (code as action)

* The model's reply is parsed for `<code>…</code>` (or markdown fences). As a fallback, the whole text is accepted if it parses as Python ([utils.py:198](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/utils.py#L198), [utils.py:217](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/utils.py#L217)). The result is executed by `python_executor`. Print logs and the last value become the observation ([agents.py:1708](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L1708), [agents.py:1726](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L1726)) `[source]`.
* **Structured mode.** With `use_structured_outputs_internally=True`, the model is asked for `{"thought": str, "code": str}` via `response_format` JSON schema (`CODEAGENT_RESPONSE_FORMAT`) ([models.py:43](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/models.py#L43), [agents.py:1705](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L1705)) `[source]`. The schema constrains only the envelope; the Python inside `code` can still be invalid `[inferred]`.
* **Composition.** One blob can call several tools. `code_1blob` completed E1 in **1 model call** (against 3 for ToolCallingAgent) `[experiment]`, with a fake model. The README says code actions use "30% fewer steps" (citing arXiv 2402.01030) ([README.md:239](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/README.md#L239)) `[claim]`. It was not reproduced: E4 is blocked.
* **No argument schema validation in the code path.** Tools are called as plain Python callables. `charge(amount="twelve")` executed and wrote `"amount": "twelve"` to the ledger (`code_wrong_type`) `[experiment]`. Missing arguments surface only as a Python `TypeError` from `forward()` (`code_missing_arg`) `[experiment]`.
* **Partial effects.** A blob that charges and then fails on a later line leaves the charge done. The error observation says only "Code execution failed at line 'report = undefined_name'…". When the (scripted) model re-sent the blob, the account was **charged twice** (`code_partial_effect_retry`: 2 charges) `[experiment]`. The runtime gives the model no signal that an effect already happened.
* Interpreter variables persist across steps (`price` reused in `code_3step`) `[experiment]`. This state lives only in memory.

#### LocalPythonExecutor and remote executors

* An AST-walking interpreter, not `exec`. Imports are limited to `BASE_BUILTIN_MODULES` (collections, datetime, itertools, math, queue, random, re, stat, statistics, time, unicodedata) plus `additional_authorized_imports`, and `"*"` allows everything ([utils.py:49](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/utils.py#L49), [local_python_executor.py:372](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/local_python_executor.py#L372)). Dunder access is blocked ([local_python_executor.py:68](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/local_python_executor.py#L68)). There are deny-lists of modules and functions ([local_python_executor.py:130](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/local_python_executor.py#L130), [local_python_executor.py:143](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/local_python_executor.py#L143)). Limits: `MAX_OPERATIONS=10_000_000`, `MAX_WHILE_ITERATIONS=1_000_000` and a 30 s timeout ([local_python_executor.py:58](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/local_python_executor.py#L58)) `[source]`.
* The timeout is thread-based. The code "cannot be forcefully killed … it will continue running in the background" ([local_python_executor.py:299](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/local_python_executor.py#L299)) `[source]`. A timed-out action can therefore still perform effects after the agent has moved on `[inferred]`.
* `final_answer` inside code raises `FinalAnswerException(BaseException)`, so that generated `except Exception` cannot swallow it ([local_python_executor.py:1572](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/local_python_executor.py#L1572)) `[source]`.
* Self-description: "It is not a security sandbox" ([local_python_executor.py:1693](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/local_python_executor.py#L1693)) `[source]`. The docs say "no local python sandbox can ever be completely secure" ([docs/source/en/tutorials/secure_code_execution.md:105](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/docs/source/en/tutorials/secure_code_execution.md#L105)) `[claim]`.
* Remote executors: E2B, Docker (Jupyter kernel gateway), Modal and Blaxel ([remote_executors.py:335](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/remote_executors.py#L335), [remote_executors.py:551](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/remote_executors.py#L551), [remote_executors.py:726](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/remote_executors.py#L726), [remote_executors.py:859](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/remote_executors.py#L859)). The Wasm/Pyodide executor was removed in `fd87137`. **Tool source code is shipped into the sandbox, and tool requirements are pip-installed there** (`send_tools` → `get_tools_definition_code`, [remote_executors.py:94](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/remote_executors.py#L94)), so tools run inside the sandbox, beside the generated code. Pickle transfer is opt-in (`allow_pickle=False` default, [remote_executors.py:74](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/remote_executors.py#L74)). Managed agents are not supported with remote executors ([agents.py:1609](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L1609)) `[source]`.

### Memory, replay and summary

* `AgentMemory` = `SystemPromptStep` + a list of `TaskStep | ActionStep | PlanningStep`. Each step type has `to_messages(summary_mode)`, and `write_memory_to_messages` concatenates them on every model call: there is no context budget or truncation beyond `truncate_content` on observations (20k characters) ([agents.py:758](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L758), [memory.py:92](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/memory.py#L92), [utils.py:257](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/utils.py#L257)) `[source]`.
* `get_full_steps()` / `get_succinct_steps()` give JSON-able dicts ([memory.py:236](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/memory.py#L236)). `replay()` only pretty-prints ([memory.py:248](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/memory.py#L248)) `[source]`. Memory steps have **no** `from_dict`. Nothing loads memory back `[source]`.

### Callbacks, streaming, cancellation

* `step_callbacks` is a list (meaning `ActionStep`) or a dict keyed by step class, dispatched by MRO ([agents.py:416](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L416), [memory.py:300](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/memory.py#L300)). They run in `_finalize_step`, **after** the step executed and **before** it is appended to `memory.steps` ([agents.py:601](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L601)) `[source]`. A callback that dumps `agent.memory` therefore lags one step unless it adds the current step itself (found while building the E2 dump) `[experiment]`. Callbacks are observers. They cannot veto an action: in E3 the callback fired after `charge` had already run `[experiment]`.
* `run(stream=True)` yields stream deltas, then `ToolCall` (before execution), `ToolOutput`, `ActionStep` and `FinalAnswerStep` `[source]`. Stopping at the `charge` `ToolCall` and closing the generator does prevent the charge. However, `_run_stream` yields inside `finally` ([agents.py:603](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L603)), so `close()` raises **`RuntimeError: generator ignored GeneratorExit`**, and the run cannot be continued `[experiment]`.
* `interrupt()` sets a flag checked only at the top of each step ([agents.py:546](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L546), [agents.py:754](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L754)). It raises `AgentError("Agent interrupted.")` out of `run()`, so the caller gets no result object. It cannot cancel an in-flight model call or tool `[source]` `[experiment]`.

### Managed agents (agent as tool)

* An agent with `name` and `description` is exposed to its manager as a tool with inputs `task` and `additional_args` ([agents.py:369](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L369)). `__call__` wraps the task in the `managed_agent.task` template and calls `self.run()` with the default `reset=True`, so each delegation starts from fresh memory. It returns the `managed_agent.report` template around the final answer, plus, optionally, a summary-mode dump of its memory (`provide_run_summary`) ([agents.py:868](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L868), [agents.py:876](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L876), [agents.py:884](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L884)) `[source]`.
* E3: the specialist saw only the system prompt and the wrapped task string, with none of the manager's history. The manager saw only "Here is the final answer from your managed agent 'specialist': …" `[experiment]`. Delegation is synchronous and nested inside the manager's tool call, with no handoff of control and no shared run identifier `[source]`.
* Specialist failure: the exception is caught by the manager's `execute_tool_call` and turned into an observation ("Error executing request to team member 'specialist' … Please try again or request to another team member"). The manager continues ([agents.py:1495](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L1495)) `[experiment]`.

### Models: local and provider support

* `Model.generate(messages, stop_sequences, response_format, tools_to_call_from) -> ChatMessage(content, tool_calls, token_usage, raw)` is the whole contract. A custom subclass works, which is how the fake model is built `[source]` `[experiment]`.
* `OpenAIServerModel` is an alias of `OpenAIModel` ([models.py:1796](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/models.py#L1796)). It takes `api_base` (LM Studio, llama.cpp, vLLM server or Ollama's OpenAI endpoint) and forwards `response_format`, `tools` and `tool_choice` `[source]`.
* `VLLMModel` (in-process vLLM) maps `response_format` to `StructuredOutputsParams(json=schema)` for real constrained decoding ([models.py:707](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/models.py#L707)). `TransformersModel` and `MLXModel` **reject** `response_format` ([models.py:1061](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/models.py#L1061), [models.py:825](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/models.py#L825)). They render tools through the chat template and rely on the text JSON parser `[source]`. `InferenceClientModel` passes structured output only for `cerebras` and `fireworks-ai` ([models.py:42](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/models.py#L42)) `[source]`.
* The only built-in retry is in `ApiModel`: rate-limit errors, detected by substring ("429", "rate limit"…), up to 3 attempts with 60 s exponential backoff ([models.py:39](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/models.py#L39), [models.py:1194](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/models.py#L1194)) `[source]`. There is no retry of invalid output beyond the error-as-observation loop.
* Execution identifiers: there is no run id. Steps carry `step_number`. Tool call ids come from the model, from `uuid4` for text-parsed calls, or from `call_{n}` for code ([agents.py:1721](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L1721)) `[source]`.

## Experiments

All results are in `experiments/smolagents/results.json`. The model and tools are fakes; no network was used.

**E1** (verified means the ledger holds exactly 1 lookup and 1 charge of 12.5):

| Variant | ToolCallingAgent | CodeAgent |
| --- | --- | --- |
| Happy path | verified, 3 model calls, 2 tool calls | 3 blobs: verified, 3 calls. **1 blob: verified, 1 call** |
| Missing argument | verified, 4 calls; schema error before execution | verified, 4 calls; Python `TypeError` from the tool |
| Wrong type | verified, 4 calls; schema error | **not verified**: `amount="twelve"` charged |
| Unparseable reply | bad JSON: verified, 4 calls | no code block: verified, 2 calls |
| Error after effect, then retry | n/a | **2 charges** |
| Premature final answer + check | refused, then verified, 4 calls | n/a |
| Budget exhausted (`max_steps=2`) | **fabricated answer returned**, 0 charges | n/a |

Framework retries: 0 in every case. Recovery always costs one extra model call and one step.
Tokens: not reported by the fake model (`null`).

**E2** (ToolCallingAgent, real `SIGKILL`, fresh-process "resume" = re-run, since no resume API exists):

| Window | resumed | charges | outcome |
| --- | --- | --- | --- |
| W1 before charge | no | 1 | `lost_progress` (lookup redone) |
| W2 inside charge, after the ledger write | no | 2 | `duplicate_effect` |
| W3 after charge was recorded | no | 2 | `duplicate_effect` |
| W4 state write | — | — | `not_applicable` (no state write) |
| W5 during delegation | no | 1 | `correct`, only because nothing had happened before the kill; the delegation was re-run |
| W6 approval | — | — | `not_applicable` (no approval) |

**E3:** approval is **not supported**. Neither step callbacks (which fire after execution) nor
stream gating (stopping the generator kills the run) can suspend a pending call and resume it,
let alone across processes. Context crosses each boundary as the task string (going in) and the
final-answer string (coming out). The manager owns its memory; the specialist's memory sits on
the specialist object and is reset on the next delegation.

**E4:** `[blocked]`. No local inference endpoint is available.

**E5** (median, p10 to p90, ms per run including agent construction and 2 ledger fsyncs):
ToolCallingAgent 16.2 (15.1 to 19.2); CodeAgent 3 blobs 27.0 (25.3 to 41.7); CodeAgent 1 blob
26.4 (23.8 to 35.7). `import smolagents`: median 487.5 ms over 5 cold interpreters. There is no
durable mode to measure.

## Which minimal abstractions make an effective agent (as seen here)

`[inferred]` from the source. The core loop is roughly 350 lines of `agents.py`, and everything else is optional.

1. **Model port**: messages plus an optional tool schema and an optional output schema in; a message with optional structured calls and token usage out.
2. **Capability descriptor**: name, description, typed input schema and output type. The same descriptor drives the prompt, the native tool schema and pre-execution validation.
3. **Bounded step loop** with a single terminal action (`final_answer`) and a step budget.
4. **Typed step log** (task, action, plan, error) with a *pure projection* into prompt messages, including a reduced "summary" projection.
5. **Rejection as observation**: invalid output, invalid arguments and failed completion checks become a recorded, typed entry that the next turn sees.
6. **Completion gate**: predicates over the log before a terminal answer is accepted.

Planning steps, managed agents, streaming and code execution are add-ons, and none of them is needed for E1.

## Code-as-action against structured calls (relevant to stack-agent)

* **Decisions per model call.** A code blob packs many capability calls into one model decision (1 call against 3 in E1) `[experiment]`. Fewer turns could help a slow local model. The "30% fewer steps" figure is a `[claim]`, and small-model accuracy is unmeasured here (E4 blocked).
* **Closed contract.** stack-agent asks for exactly one decision in a closed JSON contract and validates it before executing. A code blob is an open program. It cannot be schema-validated (E1 `code_wrong_type`), cannot be authorized per call before it starts unless every tool is wrapped, and can stop halfway after effects (E1 `code_partial_effect_retry`). This breaks *intent before execution, outcome after* at the granularity of one decision `[experiment]` `[inferred]`.
* **Validity for small models.** Constrained decoding can guarantee that a JSON decision matches a schema (vLLM, or OpenAI-compatible `response_format` where the server supports it). It can guarantee only the *envelope* of a code action, not that the Python is valid or safe (`CODEAGENT_RESPONSE_FORMAT`) `[source]` `[inferred]`. For stack-agent's invalid-decision problem with gemma, structured decoding of the existing contract is the relevant lever, not code actions.
* **Sandboxing.** The local interpreter is explicitly not a sandbox, and its timeout does not stop execution. Remote sandboxes run the *tools* inside the sandbox too, which removes the host-side allowlist and ledger from the effect path unless tools proxy back to the host `[source]`.
* **Middle ground** `[inferred]`: if fewer turns matter, a closed "batch of N `request_capability` decisions" in JSON keeps validation, authorization and an intent record per item. It still needs an explicit stop-on-first-failure rule and must report already-executed items in the observation, which is exactly the signal smolagents' code path lacks.

## Primitives not worth porting

* **Executing model-written Python in-process** (`LocalPythonExecutor`): self-declared not a sandbox, a timeout that leaves code running, and no per-call validation or authorization ([local_python_executor.py:1693](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/local_python_executor.py#L1693), [local_python_executor.py:299](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/local_python_executor.py#L299)) `[source]` `[experiment]`.
* **Code-as-action for consequential capabilities**, even when sandboxed: partial effects and unvalidated arguments `[experiment]`, and tools move into the sandbox `[source]`.
* **Budget-exhaustion fallback answer** (`provide_final_answer`): it turns a failure into a plausible fabricated success `[experiment]`. stack-agent should keep an explicit `block`/`escalate`/budget-exhausted outcome.
* **Implicit state-variable substitution** in arguments ([agents.py:1444](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L1444)) `[source]`.
* **Unordered parallel tool threads** inside one decision ([agents.py:1426](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py#L1426)), and a final answer that is accepted or rejected after sibling effects already ran `[source]`.
* **Generic "Now let's retry" text** and substring-matched rate-limit retries ([models.py:1194](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/models.py#L1194)). Either keep typed reasons (#2) or drop them.
* **Agent-as-tool delegation with string-only context**: simple, but it has no run identity, no shared durable state and no approval, and it adds nothing over a capability that calls a sub-runtime `[experiment]`.
* **Post-hoc step callbacks as a control point**: they cannot gate (E3) `[experiment]`.

## Open questions

* Does sending the closed decision schema as `response_format` to LM Studio (gemma 26B and smaller models) cut invalid decisions, and how much do latency and quality change? This needs E4 `[blocked]`.
* Do small local models produce valid `<code>` actions more often than valid JSON decisions? The papers smolagents cites use large models `[claim]`. This can be tested only under E4.
* Would a single-turn *batch* of closed decisions (the middle ground above) keep code-as-action's turn savings without losing validation and intent records? It is untested.
* Does LM Studio honour `tool_choice: "required"` and `strict` JSON schema for every local model, or only some chat templates? This could not be checked here `[blocked]` (no endpoint).
* If stack-agent adopted #2, what budget of consecutive rejections should end the run as `block`? smolagents uses only `max_steps`.
