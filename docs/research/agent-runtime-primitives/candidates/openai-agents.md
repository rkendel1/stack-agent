## Execution model

* **Loop.** `Runner.run` drives a `while True` turn loop ([`run.py#L1032`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/run.py#L1032)). Each turn calls `run_single_turn` (one model call, then tool/handoff processing) and produces a `SingleStepResult` whose `next_step` is one of `NextStepFinalOutput`, `NextStepHandoff(new_agent)`, `NextStepRunAgain`, or `NextStepInterruption(interruptions)` ([`run_internal/run_steps.py#L163-L190`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/run_internal/run_steps.py#L163)). `[source]`
* **max_turns.** Default 10 ([`run_config.py#L45`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/run_config.py#L45)); exceeding it raises `MaxTurnsExceeded` unless an `error_handlers["max_turns"]` handler supplies output ([`run.py#L1597-L1621`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/run.py#L1597)). `[source]`
* **Finality** is decided by the model: an assistant message with no tool calls (or structured output matching `output_type`), or `tool_use_behavior` such as `stop_on_first_tool`. There is no "required observations before completion" check like Chip's; the final answer is free text the runtime does not verify. `[source]` (`run_steps.py`), `[experiment]` (E3 failure case: the run "completed" with the scripted text "Charged acct-7 42." although the charge tool raised and the ledger holds 0 charges — `results.json e3.specialist_failure`).
* **Tool dispatch is concurrent.** All function calls in one model response are scheduled as `asyncio` tasks by `_FunctionToolBatchExecutor`, bounded only by optional `RunConfig.tool_execution.max_function_tool_concurrency` (default unbounded) ([`run_internal/tool_execution.py#L1548-L1665`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/run_internal/tool_execution.py#L1548)). Sibling failures cancel or drain the other tasks; completed sibling outputs are preserved (commit `1c1a28d`). `[source]` — contrast: Chip executes sequentially.
* **Handoffs** are model-chosen function calls (`transfer_to_<agent>`); only the first handoff in a response is honored, later ones get "Multiple handoffs detected, ignoring this one." ([`turn_resolution.py#L582`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/run_internal/turn_resolution.py#L582)). `[source]`
* **Guardrails.** Input guardrails run (by default) concurrently with the first model call (`run_in_parallel: bool = True`, [`guardrail.py#L100`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/guardrail.py#L100)); a tripwire raises `InputGuardrailTripwireTriggered` and cancels the model task. Output guardrails run on the final output; tool input/output guardrails wrap each function call. `[source]`
* **Streaming / cancellation.** `Runner.run_streamed` mirrors the loop ([`run_internal/run_loop.py#L1353`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/run_internal/run_loop.py#L1353)); `RunResultStreaming.cancel(mode="immediate"|"after_turn")` ([`result.py#L941`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/result.py#L941)) — `after_turn` finishes pending tools and session writes and yields a resumable `RunState`. `[source]`
* **Retries.** Only model-request retries: `ModelSettings.retry: ModelRetrySettings | None = None` ([`model_settings.py#L188`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/model_settings.py#L188)), with a replay-safety concept — a retry after the request may have reached the provider requires `RetryDecision(approve_unsafe_replay=True)` ([`retry.py#L123`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/retry.py#L123)). No tool-level retries; the default tool error policy returns an error string to the model, which may "retry" by calling again. `[source]` The underlying `openai` client has its own transport retries. `[inferred]`
* **Usage accounting.** `Usage` (requests, input/output tokens, per-request entries) aggregated on `RunContextWrapper.usage` ([`usage.py#L196`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/usage.py#L196)); E1 reported 3 requests / 45 tokens from the fake model. `[source]` `[experiment]`

## Durability (D1–D4)

Two separate mechanisms exist, and they must not be conflated:

1. **`Session` (e.g. `SQLiteSession`) is a conversation log, not a resumable execution.** The protocol is `get_items / add_items / pop_item / clear_session` ([`memory/session.py#L53-L95`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/memory/session.py#L53)). `SQLiteSession` stores one JSON row per Responses input item (`agent_messages(id, session_id, message_data, created_at)`, WAL mode) ([`memory/sqlite_session.py#L211-L258`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/memory/sqlite_session.py#L211)). It stores no current agent, no turn counter, no pending step, no approvals. Items for a turn (model tool calls + their outputs) are written **after** the turn's tools have run ([`run.py#L2033-L2090`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/run.py#L2033)); the tool-call item and its effect are therefore never recorded before the effect. `[source]` `[experiment]` (`logs/*.events.log`: `session.add_items about-to-persist [('function_call','call_1'),('function_call_output','call_1')]` appears only after `tool_start charge`).
2. **`RunState`** is a versioned JSON snapshot of the execution (`$schemaVersion` 1.21; current agent, current step, turn, generated/session items, model responses, guardrail results, approvals, tool-use tracker, trace metadata) ([`run_state.py#L248`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/run_state.py#L248), [`#L842`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/run_state.py#L842), `to_json` [`#L1899`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/run_state.py#L1899), `from_string` [`#L2329`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/run_state.py#L2329)). It is obtainable via `result.to_state()` only at an **interruption** (approval) or after `cancel(mode="after_turn")` — there is no per-turn checkpoint hook. Persisting it is the application's job. `[source]` `[experiment]` (E3 p1 `state_top_keys`, 14 KB).

| D4 Effect safety | **No.** No intent record before a tool runs, no idempotency key in the tool contract (`FunctionTool.on_invoke_tool(ctx, json_args)`), no ambiguous-outcome state. Call IDs come from the model and are not forwarded as idempotency keys. The `Model` docstring requires stable call IDs and permits omitting "an exact completed replay" ([`models/interface.py#L37-L45`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/models/interface.py#L37)) — that dedups only against outputs already in state. Docs delegate durable execution to Temporal / DBOS / Restate / Dapr integrations ([`docs/running_agents.md#L575-L593`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/docs/running_agents.md#L575)) and tell server apps to "reconcile tool side effects before retrying" ([`docs/human_in_the_loop.md#L216-L218`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/docs/human_in_the_loop.md#L216)). | `[source]` `[experiment]` W2, W4, W2_after_approval → duplicate charge; `[claim]` integrations not evaluated. |

## Crash-window table (E2, real SIGKILL, fresh-process resume)

Store: `SQLiteSession` file DB for W1–W5; `RunState.to_string()` file (atomic rename + fsync) plus the same SQLiteSession for W6 and the extra window. Source: `results.json e2.windows`.

| Window | Kill point | Resume mechanism | Resumed | Charges | State ≙ ledger | Progress lost | Manual intervention | Outcome |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| W1 | `on_tool_start(charge)` | new `Runner.run(agent,"continue",session)` | yes | 1 | yes | no (charge decision re-asked of model; lookup not redone) | detect incomplete run, supply new input | `correct` |
| W2 | inside `charge` after ledger fsync | same | yes | **2** | no (session shows 1) | yes | same | **`duplicate_effect`** |
| W3 | next model call (turn committed) | same | yes | 1 | yes | no | same; an extra user turn enters history | `correct` |
| W4 | `add_items` of charge batch, before commit | same | yes | **2** | no | yes | same | **`duplicate_effect`** |
| W5 | `on_handoff` Triage→Specialist | same (no RunState exists yet) | yes | 1 | yes | handoff redone (no effect) | same; restarts at entry agent | `correct` |
| W6 | suspended after RunState saved | `RunState.from_string` + `approve` + `Runner.run(agent,state)` | yes | 1 | yes | no | approve (the intended HITL step) | `correct` |
| W2 after approval (extra) | inside approved `charge` in resumed run | reload the only saved RunState, approve again | yes | **2** | no | yes | re-approve | **`duplicate_effect`** |

`[experiment]` Pattern: anything is safe only if it is either before the effect or after the turn commit; the window "effect done, turn not committed" duplicates, and the SDK cannot tell (no intent record → no `OutcomeUncertain`).

## Handoffs and approval (E3)

* **Control transfer vs agent-as-tool.** `handoff(agent)` transfers control: the run continues with the new agent as `current_agent`; `Agent.as_tool()` instead runs a nested run and returns its output as a tool result (interruptions inside it surface on the outer run). `[source]` ([`handoffs/__init__.py#L126-L190`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/handoffs/__init__.py#L126)), `[claim]` (`docs/human_in_the_loop.md` L5).
* **Context at the boundary.** Default: the full history (original input + all items, including the `transfer_to_specialist` call and its output `{"assistant": "specialist"}`) is passed to the Specialist. `[experiment]` (`e3.p1.model_inputs[1]`). Configurable: `Handoff.input_filter` / `RunConfig.handoff_input_filter` (e.g. `extensions/handoff_filters.py`), or `RunConfig.nest_handoff_history=True` (default False, [`run_config.py#L385`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/run_config.py#L385)) which collapses prior transcript into one summary message via `handoff_history_mapper` ([`handoffs/history.py#L83`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/handoffs/history.py#L83), [`#L386`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/handoffs/history.py#L386)). The app `context` object is shared, not copied, across handoffs. `[source]`
* **State owner** at each step: the single `Runner.run` invocation (in memory) → at suspension, the application's stored `RunState` JSON → after approval, the resuming `Runner.run`. The Session only mirrors items (at suspension it held the pending `function_call:charge:call_2` with no output). `[experiment]`
* **Execution identifiers.** Model-supplied `call_id`s (here `call_0..call_3`), `trace_id`/group in RunState, Session `session_id`. No run ID independent of trace. `[experiment]` `[source]`
* **Approval.** `function_tool(needs_approval=True | callable)` → `NextStepInterruption` with `ToolApprovalItem`s; `state.approve(item, always_approve=False)` / `reject(...)` ([`run_state.py#L1380-L1410`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/run_state.py#L1380)). Approval survived a SIGKILL'd process (W6 `correct`, resumed at `specialist` with one model call). `[experiment]` Snapshot replay protection ("cannot resume the same snapshot twice") is the application's job `[claim]` (`docs/human_in_the_loop.md` L216) — W2_after_approval shows the consequence. `[experiment]`
* **Specialist failure.** A raising tool becomes the model-visible output "An error occurred while running the tool. Please try again." (`default_tool_error_function`, [`tool.py#L1997`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/tool.py#L1997)); the run continues and the model decides. Nothing surfaces to the caller as a failed outcome. `[experiment]` `[source]`

## Provider / local-model notes

* `Model` (`get_response`, `stream_response`) and `ModelProvider.get_model(name)` are small ABCs ([`models/interface.py#L37-L150`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/models/interface.py#L37)); a 60-line fake was enough for every experiment. Built-ins: `OpenAIResponsesModel`, `OpenAIChatCompletionsModel` (any OpenAI-compatible Chat Completions endpoint, e.g. local servers), `MultiProvider` prefix routing, and `extensions/models/litellm_model.py` / `any_llm_model.py`. Chat Completions output is converted to Responses items with placeholder IDs (`FAKE_RESPONSES_ID`). `[source]`
* **Malformed tool calls** (important for small local models) `[experiment]` (`results.json e1.invalid_args_handled`):
  * missing required argument → Pydantic validation `ModelBehaviorError` inside the tool wrapper, converted to the generic error string; body not run; model got another turn and succeeded (4 model calls, 1 charge);
  * invalid JSON `{"account": "acct-7", "amount": 4` → same path (`_parse_function_tool_json_input`, [`tool.py#L1963-L1985`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/tool.py#L1963));
  * unknown tool name → **run aborts** with `ModelBehaviorError: Tool chrage not found in agent payer` by default; opt-in `RunConfig.tool_not_found_behavior="return_error_to_model"` ([`run_config.py#L498`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/run_config.py#L498), [`turn_resolution.py#L3830-L3846`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/run_internal/turn_resolution.py#L3830)).
  * The default error text is deliberately generic ("Please try again"), so a small model gets no hint *what* was wrong unless `failure_error_function` / `RunConfig.tool_error_formatter` is set. No argument repair. `[source]`
* Strict JSON schemas are generated from function signatures/docstrings (`function_schema.py`, `strict_json_schema=True` → `ensure_strict_json_schema`, [`tool.py#L635`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/tool.py#L635)); strict mode helps hosted structured-output decoding but is not enforced by local servers that ignore `strict`. `[source]` `[inferred]`
* E4 `[blocked]`: no local inference endpoint.

## Overhead (E5)

N = 50 after 1 warm-up, same machine, fake model + fake tools (ledger fsync in all modes). `[experiment]`

| Mode | p10 ms | median ms | p90 ms |
| --- | --- | --- | --- |
| no session | 10.4 | 11.9 | 17.4 |
| `SQLiteSession(":memory:")` | 13.5 | 16.3 | 25.2 |
| `SQLiteSession(file)` (durable) | 17.6 | 20.1 | 26.7 |

## Primitives worth porting

1. **Typed turn result / NextStep sum type** — `SingleStepResult{model_response, pre_step_items, new_step_items, next_step: FinalOutput|Handoff|RunAgain|Interruption}` ([`run_steps.py#L163-L215`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/run_internal/run_steps.py#L163)). Guarantee: each turn ends in exactly one explicit transition, and "suspended for approval" is a first-class state. Rust sketch: chip-core already has `request_capability | complete | escalate | block`; add an `Interrupted { pending: Vec<PendingApproval> }` turn outcome that FeltDB records as a task state (lease released, no executor call), and keep `complete` gated by required observations (stronger than the SDK).
2. **Serializable, versioned suspension snapshot + approve/reject API** — `RunState` with `$schemaVersion`, migrations-on-read summaries, `approve(item, always_approve)`/`reject`, sticky decisions ([`run_state.py#L248-L320`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/run_state.py#L248), [`#L1380`](https://github.com/openai/openai-agents-python/blob/64cd5dfc5a1579870dcbed0ea42b27aa84033fee/src/agents/run_state.py#L1380)). Guarantee: approval survives process death (W6). Rust sketch: an `ApprovalRequest { task_id, intent_id, capability, args_digest }` record in FeltDB, decided via a fenced `decide(intent_id, Approve|Reject, sticky)`; the decision is consumed atomically with the lease (fixes the SDK's "resume the same snapshot twice" gap and W2_after_approval because Chip already records the intent before execution and blocks on `OutcomeUncertain`).
3. **Model-feedback policy for malformed/unknown tool calls** — invalid JSON / schema failure become a tool-result error to the model; unknown-tool behavior is a policy switch (`raise_error` | `return_error_to_model`), and the error text is pluggable (`tool_error_formatter`). Guarantee: no executor call on invalid args, bounded by max_turns. Rust sketch: in chip-core validation, map `ValidationError` → an `Observation::Rejected{reason}` fed to the next model turn (count against a per-task malformed-call budget), never to the executor; make the message specific (missing field names) since small local models need it — improving on the SDK's generic default.

Also notable: replay-safety-gated model retries (`approve_unsafe_replay`) and the per-call-id "skip if output already recorded" rule on resume, which Chip's observation reconciliation already subsumes.

## Primitives not worth porting

* **Session-as-durability** (append items after the turn): it is what produced W2/W4 duplicates; FeltDB's intent→observation→outcome is strictly stronger.
* **Concurrent tool fan-out by default**: conflicts with Chip's sequential, per-intent authorization; would need multi-intent reconciliation.
* **Model-chosen handoffs with shared full history**: no handoffs in stack-agent; if ever added, prefer the filtered/nested history mapper explicitly.
* **Generic "Please try again" tool errors and silent tool-failure → model** (final answer can claim success; E3 failure case).
* **Tracing backend/exporter stack** (OpenAI-backend-centric, best-effort batching).

## Open questions

* The Temporal / DBOS / Restate / Dapr integrations claim durable execution `[claim]`; whether they record intents before tools or only replay activities was not evaluated here.
* `cancel(mode="after_turn")` produces a resumable RunState; whether a graceful-shutdown path could approximate per-turn checkpoints (W1/W3 analogs) was not tested.
* Behavior of `OpenAIChatCompletionsModel` against small local servers returning `arguments: ""` or non-object JSON (handled as `{}` / error per `_parse_function_tool_json_input`) is `[blocked]` with E4.
